# Trigger Events 设计重构（2026-03-22）

## 目标
1. 基于 `xcdocs` 与 `ui-ux-pro-max` 重新审视 `trigger events` 行视觉层次与可操作性。
2. 在不改变功能语义的前提下，提升可读性、编辑心智模型与键盘/无障碍提示。

## 依据
1. `xcdocs`：
   - `/documentation/SwiftUI/GroupBox`
   - `/documentation/SwiftUI/Picking-Container-Views-for-Your-Content#Group-views-and-controls-for-data-entry`
   - 结论：对于一组相关输入控件，应优先使用能表达录入分组语义的容器，而不是为“表格感”牺牲编辑可读性。
2. `ui-ux-pro-max`：
   - UX 高优先项：任务导向分组、清晰层级、可扫描摘要、充足点击目标、非颜色单一反馈。

## 实施
1. `trigger events` 从“表头 + 行卡片”继续演进为“步骤分组编辑器”：
   - 每个步骤使用独立 `GroupBox` 承载完整编辑内容；
   - 不再强调列式浏览，改为强调单步配置闭环。
2. 分组头信息设计：
   - 步骤编号改为圆形徽标；
   - 标题区同时展示步骤名、类型标签、步骤摘要；
   - 顺序调整按钮与分组头合并，操作位置稳定。
3. 分组内容结构：
   - 第一行放置类型切换与延时设置；
   - 第二层放置按键编辑区，单键与组合键保持同一视觉语法；
   - 保留 `.bordered` 顺序按钮与无障碍标签。
4. 信息摘要增强：
   - 分组头部摘要不再只显示“单键/组合键 + 延时”；
   - 改为直接展示真实按键名组合，帮助用户在长序列中快速确认每一步动作。
5. 长列表优化：
   - 步骤内容支持折叠/展开，降低多步骤宏序列的纵向占用；
   - 提供“展开全部 / 折叠全部”操作，便于在总览与细编之间切换；
   - 头部摘要在组合键较多时自动截断，保证头部层级稳定。
6. 视觉完成度增强：
   - 头部摘要拆为更紧凑的 capsule badge，而不是单行说明文本；
   - 组合键编辑区同步显示 token 预览，让“当前组合是什么”在编辑态也一眼可见。
7. 视觉主次收敛：
   - badge 按语义分为主键、延时、隐藏数量、空态四类；
   - 主键 badge 更强调，延时 badge 次强调，计数/空态更弱，形成稳定视觉层级；
   - 单键编辑区也采用 token 预览，统一单键与组合键的编辑语法。
8. 主动作锚点：
   - 默认把步骤的第一个有效 key 视为主动作；
   - 头部与编辑区都优先强调这个 primary key，其余按键退为 secondary；
   - 长组合键场景下更容易一眼抓到“这一步主要做什么”。
9. Inspector 展开态：
   - 展开区改为左右两栏：左侧元信息（类型、延时），右侧按键编辑；
   - 当前步骤增加轻量高亮描边与底色，长序列中更容易定位正在编辑的步骤。
